# SiGame Helper — заметки для работы над проектом

Программа для подготовки медиа к паками SIGame / SIQuester: скачать, нарезать,
сжать. Главное ограничение, ради которого всё затевалось: **пак в SIQuester
не должен превышать 150 МБ**.

Автор — не программист. Объяснять нужно простым языком, без жаргона, и всегда
доводить проверку до того, **что видит человек на экране**, а не до «функция
возвращает правильное значение». На этом уже обжигались дважды.

## Из чего состоит

```
installer.py            Единственная точка входа. Он же установщик, он же
                        запускалка: есть рядом runtime (или .venv) — открывает
                        программу, нет — показывает окно установки.
SiGame Helper.exe       Собранный installer.py. Лежит в репозитории, чтобы
                        попадать в архив «Download ZIP» и в релизы.
backend/run.py          Запуск сервера и окна (PyWebView + WebView2).
backend/app/            FastAPI: routers/ — HTTP, core/ — вся работа.
frontend/               React + Vite + Tailwind. Собирается ВНУТРЬ бэкенда,
                        в backend/app/static — поэтому у пользователя нет Node.
assets/icon.ico         Иконка программы и окна.
scripts/                build.bat (фронтенд), build-exe.bat (exe),
                        dev.bat (разработка), reveal.ps1 (проводник).
workspace-test/         Файлы для проверок. Всё тестовое — только сюда.
```

Настройки, кэш и журнал: `%APPDATA%\SiGameHelper`. Журнал — `logs\app.log`,
он часто оказывается единственным способом понять, что случилось в окне.

## Как собирать

```bat
scripts\build.bat       фронтенд -> backend/app/static
scripts\build-exe.bat   собирает SiGame Helper.exe (фронтенд соберите раньше!)
```

**Порядок важен.** Если собрать .exe раньше фронтенда, внутрь попадёт старый
интерфейс. Ровно так уже выпускали релиз со старым кодом.

После правок бэкенда или фронтенда программу надо **перезапустить** и
проверить глазами: `SiGame Helper.exe` в папке проекта запускает её через
`.venv`, установка при этом не предлагается.

Сервер поднимается на `127.0.0.1:8756`.

## Решения, которые уже приняты (и почему)

**AV1 + Opus в MP4** — основной формат паков. Проверено на трёх устройствах,
включая телефон и слабый Athlon: играет везде. Менять не нужно.

**SIQuester не показывает AV1**, хотя SIGame играет. Это его ограничение
(старый механизм Windows, расширения из Store туда не доходят). Превью сжатых
файлов в редакторе пака не будет — это не баг.

**Кратность сжатия зависит от исходника, а не от пресета.** Уже сжатый AV1
даёт ~1.4x, H.264 с высоким битрейтом — ~5x, «сырой» файл — до 100x. Если
человек жалуется на слабое сжатие, первым делом смотреть кодек и битрейт
исходника.

**Обходы блокировок (Zapret) и загрузка.** Без прокси добавляем
`--proxy "" --force-ipv4` и чистим переменные окружения с прокси. Отдельные
ролики всё равно не берутся — это провайдер, программа тут бессильна.

**Установка.** Python не требуется: скачивается переносимая сборка в `runtime`.
Обязательны `--no-build-isolation` и заранее поставленные `setuptools`,
иначе pip падает на пакетах без готовых «колёс» (proxy-tools).

**Папки:** «Скачанное» и «Обработанное». Раньше были `_downloads` и
`_processed` — выглядели как служебный мусор.

## Что уже пробовали и отбросили

- **Перетаскивание файлов в окно «руками»** — обработчики WinForms на форме и
  на браузерном контроле плюс `AllowExternalDrop = False`. Именно этот запрет
  и ломал всё: стоит забрать бросок у страницы, и Windows рисует
  перечёркнутый курсор — событие не достаётся никому.

  Рабочее решение уже есть в самом pywebview: страница ловит бросок обычным
  образом, WebView2 передаёт окну сами файлы, и в обработчике
  `window.dom.document.events.drop` у каждого файла лежит настоящий путь —
  поле `pywebviewFullPath`. `AllowExternalDrop` трогать нельзя. На странице
  нужен `preventDefault` на `dragover`, иначе броска не будет вовсе.
- **`--impersonate chrome`** для обхода блокировок — стало хуже
  (`Connection reset`), откатили, `curl_cffi` убрали.
- **Скачивание в H.264 вместо AV1** — смысла нет: получаем худший исходник.
  Для монтажа правильнее скачать лучшее и перегнать пресетом
  «Конвертация в MP4 (H.264)».
- **Два отдельных файла** (установщик + запускалка) — путало людей: в архиве
  с GitHub оказывался не тот, что в релизе. Свели в один.

## Грабли, на которые уже наступали

**Правка файлов через heredoc в Bash съедает обратные слэши.** `\n` внутри
строки превращается в настоящий перевод строки, `\\` — в один символ. Из-за
этого уже ломались `._pth`, регулярные выражения и пути. Для файлов с
экранированием пользоваться Write или собирать строки через `chr(92)`.

**Скрипт правки может упасть на середине** и записать половину изменений —
так программа один раз перестала запускаться вовсе. После каждой правки
запускать программу, а не только проверять синтаксис.

**Проверять надо результат, а не вызов.** `explain_failure` однажды осталась
мёртвым кодом: функция работала, но её никто не вызывал, и подсказки не
доходили до экрана. Иконку окна дважды «починили» так, что в панели задач она
не менялась.

**Устаревшие замыкания в React.** Обработчики на `window` видят снимок из
прошлого рендера. Уже ломало маски в редакторе картинок и магнит на
таймлайне — лечится ссылками (`useRef`).

**PyWebView на Windows игнорирует параметр `icon`** и берёт значок у
`pythonw.exe`. Иконку ставим сами через свойство формы, а панели задач нужен
ещё и `SetCurrentProcessExplicitAppUserModelID`.
